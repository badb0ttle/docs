# Ego Browser 与 AI 辅助验证

## 为什么需要浏览器验证

只读后端代码和接口文档，无法确认用户最终看到的页面是否真的符合预期。AIGun AI 的不少问题涉及 GoldRiver、LangTools 等页面、历史 Trace 和前端字段映射，因此我使用 Ego Browser 进行登录态下的页面观察和流程验证，把“接口返回了什么”和“页面展示了什么”放在同一条证据链中。

## 一次验证的基本流程

```text
选择隔离浏览器任务空间
          │
          ▼
确认页面、任务 ID 和时间窗口
          │
          ▼
观察 DOM / 页面文本 / 截图
          │
          ▼
执行点击、输入和筛选操作
          │
          ▼
对比页面结果与 Trace、接口 payload
          │
          ▼
记录复现步骤和验证结论
```

浏览器自动化最有价值的地方不是“代替人点击”，而是可以快速重复同一条验证路径，并同时保留页面证据。遇到结果不一致时，我会先确认页面使用的是哪条接口、哪个 Trace 和哪一版数据，再回到后端定位。

## 在排障和 QA 中的使用场景

- 检查 AI 分析区块是否因 observation 存在性正确显示。
- 验证代币、股票、过滤原因和耗时字段是否被前端正确映射。
- 对比提示词测试、重新分析和历史结果是否使用了同一模型与输入。
- 检查语言切换、注册、交易历史等固定流程的页面行为。
- 在部署后做一次端到端冒烟验证，并把异常截图和任务 ID 反馈给开发与产品。

## 安全边界

浏览器任务必须使用隔离环境，凭证由已有登录态管理；不在文章、日志、截图或案例中保存 Cookie、Token、密码和私人数据。页面看到的内容也不能直接当成根因，仍需要回到原始接口、Trace 和日志进行确认。

## 小结

Ego Browser 让浏览器成为可重复的验证工具：页面负责证明用户体验，Trace 和接口负责证明后端事实，三者结合可以明显缩短联调和排障时间。
